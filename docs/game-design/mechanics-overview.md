## 1. Ядро: ход и бой

### 1.1 Пошаговая раундовая система

Раунд = фазы фракций в фиксированном порядке `player → allies → enemies → neutrals`, затем `environment-turn` (тик тайловых эффектов) и `round-recovery` (удаление мёртвых, сброс флагов). В начале хода фракции восстанавливаются AP, тикают статусы и кулдауны.

- Ручки: `maxAp` у шаблона сущности (по умолчанию 1); `factionId` (`player/allies/enemies/neutrals` — можно делать союзников и нейтралов).
- Файлы: `src/simulation/simulation.ts`, `docs/agents/TURN_FLOW.md`.

### 1.2 Очки действий (AP)

Стоимости: MOVE = `moveCost` террейна целевой клетки (fallback 1); ATTACK/INTERACT/EQUIP/UNEQUIP = 1; END_TURN = 0; USE_ABILITY = `apCost` шаблона (число или `'all'` — все текущие AP, максимум 3); USE_ITEM = `apCost` предмета. AP — главный балансный рычаг.

- Файлы: `src/simulation/systems/action-cost-resolver.ts`, `src/utils/constants.ts` (`MAX_ABILITY_ALL_AP_COST = 3`).

### 1.3 Атака, урон, броня, HP

Базовая атака существует в двух формах: направленная (bump-attack: движение во врага = атака, legacy) и позиционная (выбор цели на клетке, `AttackAction.targetPosition`). Дальность берётся из шаблона оружия: дистанция Чебышёва до цели должна быть в [`weapon.minRange`, `weapon.range`] (оба int ≥ 1, default 1 — чистая мили-атака, бьёт все 8 соседних клеток; общий предикат `isInWeaponRange`), требуется прямая видимость (LOS через FOV — радиус обзора тоже квадратный, Чебышёв); валидация отвечает reason-кодами `no_target_at_tile`/`target_out_of_range`/`target_too_close`/`no_line_of_sight`. При `minRange > 1` оружие не бьёт в упор вообще: bump в соседнюю клетку отклоняется валидацией с reason-кодом `too_close_for_ranged_weapon` (игрок видит тост, ход не тратится). Таргетинг в UI — режим по образцу броска расходника, слот 0 хотбара закреплён за базовой атакой; подсвечивается вся зона досягаемости (`getBasicAttackRangeCells`), клик по валидной цели бьёт, клик по любой другой клетке отменяет режим без атаки. Клик/наведение по видимому врагу в обычном режиме (без входа в таргетинг): если цель уже в зоне поражения текущего оружия — наведение показывает эмуляцию подготовки атаки (тусклая зона досягаемости от текущей позиции игрока + подсветка цели + пунктирная линия к ней, `RenderInput.enemyHoverOverlay`; при цели вне зоны линия идёт от последнего шага автопути до атакующей клетки — оттуда будет бить атака), а клик сразу выполняет позиционную атаку; если цель вне зоны — клик фиксирует автопуть до ближайшей атакующей клетки (проходимая клетка, Чебышёв до цели ∈ [minRange, range], прямая видимость из неё на цель — query `findNearestAttackPosition`; приоритет выбора — визуально ближайшая к игроку клетка по евклидовой дистанции, затем кратчайший путь), и по достижении выполняется позиционная атака по текущей позиции врага (цель отслеживается по entityId, клетка пересчитывается на каждом шаге); зона досягаемости от текущей позиции показывается при наведении в любом случае. Melee унифицирован той же схемой (путь до соседней атакующей клетки + позиционная атака); bump-форма остаётся только на клавиатуре (moveOrAttack). Если атакующей клетки не найдено — fallback: автопуть в клетку врага (старое поведение). Броня вычитается **только из физического** урона; магический урон броню игнорирует. Пола «минимум 1 урона» нет (снят 2026-08-10): броня может полностью обнулить физический урон; нижняя граница 1 сохраняется только для процентного урона и выражена явно — `min: 1` в `ParametrizedValue` правил (тики яда 8% maxHp, горения 10% maxHp). Промахов и роллов попадания нет (статы уклонения/точности/шанса крита и событие `ENTITY_MISSED` удалены 2026-08-07). Урон оружия — рейнж `{min, max}` из шаблона: конкретное значение роллится в момент удара со смещением вверх от ловкости атакующего (см. §1.4). Крит — глобальное контентное правило `core_crit_on_dazed_stunned`: урон с тегом `delivery.weapon` (базовые атаки и оружейные скиллы; урон способностей, тиков и столкновений не критует) по цели со статусом `dazed`/`stunned` умножается на `critMultiplier` атакующего и помечается тегом `crit` (строка в боевом логе + число урона отображается как «-N!» чуть крупнее обычной цифры урона). Яд и оглушение оружия (`weapon_poison_on_hit`, `weapon_blunt_daze`) — тоже детерминированные (срабатывают всегда). HP: игрок — 50 + vit×10; враги — `health.max` шаблона. Двери и пропы тоже разрушаемы (имеют HP/броню).

- Ручки: `weapon.damage {min,max}`/`weapon.range`/`weapon.minRange`/`baseArmor` экипировки игрока; у врага — прямые поля шаблона сущности `attack` (профиль атаки: `damage {min,max}`, `range`/`minRange`, `damageDistribution`, `tags`), `armor`, `modifiers`; правила `modifyDamage`.
- Файлы: `src/simulation/systems/actions/attack-action.ts`, `src/simulation/systems/damage/apply-damage.ts`, `src/presentation/autoPathController.ts` (автопуть до атакующей клетки).

### 1.4 Характеристики и урон оружия

Базовые: `str, dex, int, vit`. Производные: рейнж урона оружия, броня, maxHp, critMultiplier (база 1.5), throwRange (база 0 — бонус к дальности бросков расходников, итог = `range` шаблона + стат). Модификаторы `StatModifier` (add/multiply, порядок multiply → add, уникальность по `source`; к рейнжу урона add/multiply применяются к обоим концам). Derived-кэш (`actor.maxHp`/`damage`/`armor`/`critMultiplier`, обновляется `recalculateActorStats`) хранит итоговые значения — базу с уже применёнными stat-модификаторами; боевой расчёт (`getEffectiveArmor`, `rollWeaponDamage` и др.) считает то же из базы через `getEffective*`-функции.

Урон оружия — рейнж `{min, max}` из шаблона (`weapon.damage`); формулы урона оружия (`damageFormulaId`, скейлинг от статов) удалены 2026-08-08. Конкретное значение роллится в момент удара (`rollWeaponDamage`) по формуле `min + round((max − min) × u^(1/(1 + dex·k)))`, где `u` — равномерный ролл из `state.runtimeRng`, `k = DEX_DAMAGE_BIAS_K = 0.05`: чем выше эффективная ловкость атакующего, тем сильнее распределение смещено к `max`. Без оружия действует шаблон `unarmed` (рейнж {1,1}).

- Файлы: `src/simulation/systems/stats/` (`base-resolver.ts`, `effective-stats.ts`, `weapon-damage-roll.ts`, `modifier-engine.ts`), `src/simulation/characterCreation.ts`.

### 1.5 Иерархические теги

Каноническая классификация — теги вида `a.b.c`: проверка по родителю работает автоматически (`damage.physical.slashing` удовлетворяет `damage.physical`). Теги на оружии/способностях/сущностях — главный механизм привязки правил.

- Семейства: `damage.physical.{slashing,piercing,blunt}`, `damage.magical.{fire,electric,poison,frost}`; `attack.{melee,ranged}`; `target.{single,multi,aoe}`; `delivery.{weapon,ability,projectile,spell,movement,unarmed}`; `effect.{burn,knockback}`; `reaction.counter`; `displacement.push`; `collision.*`; `status.*`; объектные `flammable`, `contains.oil`, `prop.barrel`; террейн `ground`.
- У оружия — `damageDistribution`: взвешенное распределение типов урона (например, «80% рубящий + 20% огненный»); запись с максимальным весом = основной тип.
- Файлы: `src/simulation/systems/tags/`.

## 2. Способности (скиллы)

Способность = контентный шаблон (discriminated union по `kind`) + исполнитель, собираемый фабрикой из параметров шаблона (`KIND_FACTORIES` в `getSkillExecutor`). Урон способностей — фиксированные значения из шаблона, без скейлинга от характеристик и уровня (реестр формул `damageFormula.ts` удалён 2026-08-12); оружейные виды (`cleave`, `suddenStrike`) бьют роллом экипированного оружия. Таргетинг: `self`, `single{range}`, `multi{range,count}`, `area{range,aoeRadius}`. Небоевые self-способности (поиск, бафы на себя) применяются мгновенно, без выбора клетки: `GameSession.beginTargeting` спрашивает query `Simulation.getAbilityAutoSelfTarget` — авто-каст, если единственная валидная цель и вся зона действия (`getAffectedPositions`) — клетка самого игрока; боевые self-AoE (`ground_slam`) по-прежнему требуют подтверждения клеткой. То же правило покроет будущие скиллы «на себя/союзника»: без союзников в радиусе валидная цель одна — каст на себя мгновенный.

Ручки шаблона: `cooldown`, `apCost` (число или `'all'`), `damageTag` (ability-based урон), `requiredWeaponTags` (привязка к типу оружия), `aiPreparable` (AI может готовить на следующий ход), `tags`, `ruleIds`.

Существующие (10): `fireball` (AoE 3×3: центр 20, периметр 10; огонь), `magic_slap` (до 3 целей по 12, электричество, `aiPreparable`), `dash` (рывок на 2 клетки, открывает двери, урон столкновения 5), `swoop` (прыжок + удар по земле: урон и отталкивание по кольцу вокруг точки приземления, центр не задевается; клетка с существом — «подставка»: двойной урон ему (без оглушения), его отпихивает на ближайшую свободную клетку, кастер приземляется на его место, удар по кольцу проходит и здесь; недвижимую жертву отпихнуть нельзя — отбрасывает кастера, `aiPreparable`), `cleave` (по цели и боковым клеткам, требует melee-оружие), `sudden_strike` (одиночный удар, требует melee-оружие), `counterattack` (self-бафф статуса на 2 хода), `bulwark` (self-бафф неуязвимости на 1 ход, босс), `guardian_swoop` (Налёт босса: прыжок на 3, та же подставка/отскок, `aiPreparable`), `ground_slam` (Удар по земле босса: AoE 5×5 вокруг себя + dazed выжившим, `aiPreparable`).

Шаблон — discriminated union по `kind`; все виды несут параметры механики в шаблоне и собирают исполнитель фабрикой (новый экземпляр существующего вида — чистый контент): `selfBuff` (`statusType`, `duration`), `swoop` (`jumpRadius`, `aoeRadius`, `baseDamage`), `groundSlam` (`radius`, `baseDamage`), `fireball` (`range`, `aoeRadius`, `centerDamage`, `aoeDamage`), `magicSlap` (`range`, `targetCount`, `baseDamage`), `dash` (`distance`, `bumpDamage`), `suddenStrike` (`silenceDuration`), `cleave` (без параметров), `throw` (`range`, `baseDamage`, `pushDistance` — бросок по одной цели в прямой видимости с отталкиванием; урон и `dazed` при столкновении — глобальные правила `collision_*`; первый контентный экземпляр — `stone_throw` пращи).

- Файлы: `src/simulation/skills/`, `src/content/templates/abilities/`.
- Ограничение: новая механика способности = новый член union + фабрика в движке (код); новый экземпляр существующего вида — чистый контент.

## 3. Статусы

Типы статусов — контентные шаблоны в `src/content/templates/statuses/` (актуальный перечень — там и в реестре). Экземпляр: `duration` (в ходах фракции носителя), `value`, `stacks`, `statModifiers`. Тик — в начале хода фракции носителя (у дверей/пропов — в `environment-turn`).

Система конфликтов: категории (`elemental/physical/mental/poison/generic`) с `categoryPriority` — один статус на категорию; `mutuallyExclusiveWith` (снимает старый); `blockedBy` (блокирует наложение).

Особые эффекты: `stunned` — пропуск хода, сбрасывает подготовленные скиллы; `silenced` — запрет способностей; `wet` снимает и несовместим с `burning`; `burning`↔`frozen` взаимоисключающи; `stunned` снимает `dazed`; `dazed` — −1 к maxAp при восстановлении AP (через `statModifiers` шаблона). Тики урона (яд 8% maxHp магический, горение 10% maxHp, кровотечение — плоские 2 HP внутреннего урона `damage.internal.bleeding`, с 2026-08-27; бронёй не режется — броня работает только против внешнего физического урона `damage.physical.*`) заданы правилами — перенастраиваются контентом. `bulwark` («Глухая оборона» босса) — движковая семантика: полный иммунитет к урону (событие с damage 0 эмитится — статусы накладываются) и к толчкам, запрет всех действий носителя, кроме END_TURN, **без** сброса подготовленного скилла (отличие от `stunned`). `rooted` («Обездвижен») — движковая семантика: запрет самостоятельного перемещения (MOVE отклоняется с reason-кодом `actor_rooted`, рывок и прыжок недоступны), атаки и способности по целям в досягаемости разрешены, внешние перемещения (PUSH) не блокируются; hunter-AI под rooted не делает шагов и атакует только соседнюю цель.

Модификаторы характеристик статуса: поле `statModifiers` шаблона статуса (`StatusTemplateSchema`) применяется к актору при наложении (source — `instanceId` экземпляра) и снимается на любом пути удаления (expire, вытеснение, стеки → 0, конец `stunned`). Доступные статы — общий `StatNameSchema`, включая `maxAp`: восстановление AP читает эффективный maxAp (`getEffectiveMaxAp`), снапшот `getPlayerStats` тоже отдаёт эффективное значение. При обновлении длительности существующего статуса модификаторы не переприменяются (как и `ruleIds`); `ap` не клампится при спадании бафа. Поле `statModifiers` на экземпляре `StatusEffect` — мёртвый задел, движком не читается.

- Ручки: шаблон статуса (`ruleIds`, `statModifiers`, категория, приоритет, конфликты), параметры наложения (duration/value/stacks).
- Файлы: `src/simulation/systems/status-effect-ticker.ts`, `src/simulation/systems/statuses/status-stat-modifiers.ts`, `src/content/templates/statuses/`.

## 4. Контентные правила — главный инструмент дизайнера

Декларативный DSL: **триггер (событие/интент + теги) → условия → эффект → селектор целей**. Привязка к любому контенту через `ruleIds`. Новый контент с новым поведением часто создаётся **без изменения кода**. Порядок исполнения: слои `source → target → world (global → tileEffect → tileEffectStatus → object → tileIntrinsic) → radius → global`, внутри — `priority`, затем id. Слой `global` (2026-08-30): правила с `reach: 'global'` собираются от всех живых акторов независимо от дистанции (для on-death/on-remove механик реликвий), с дедупликацией против остальных слоёв.

- **Эффекты:** `applyStatus`, `dealDamage`, `heal`, `restoreAp`, `consumeAp`, `modifyDamage` (multiply/add + addTags; только интенты DAMAGE/DAMAGE_TILE), `counterAttack`, `applyTileEffectStatus`, `spawnTileEffect`.
- **Условия:** `chance`, `hasStatus`, `hasTag`, `entityHasTag`, `inTileEffect`, `tileEffectHasStatus`, `eventFieldEquals`, `eventRole`, `notSelfHit`, `and/or/not`.
- **Селекторы:** `eventTarget`, `eventSource`, `self`, `collisionTarget`, `eventTileEffect`, `allInRadius`, `nearestEnemy`, `tilesInRadius`, `positionsInRadius`.
- **Числа (`ParametrizedValue`):** константа, ссылка на контекст (`eventDamage/eventAmount/eventDuration/eventStacks/eventMaxHp` × multiply, min, round) или `ownerParam` (ролленное значение rule-аффикса предмета).

Готовые правила-образцы для переиспользования: контратака (50%), вода→`wet`, масло→`oiled`, поджог масла огнём, урон и горение при входе в горящее масло, распространение горения, отравление от piercing/slashing (40%), ошеломление от blunt (25%), шипы брони, восстановление AP при ударе (15%), множители огненного урона (×1.5, +2, ×1.2 по горящим), урон и daze при столкновении после толчка, разлив масла из бочек с `contains.oil`, поджог `flammable`-объектов, лечение алтарём, урон колючек. Кровавая ветка (2026-08-30): открытие/продление/добивание по `bleeding`, кровавые шипы брони, берсерк от собственной крови, реликвии «плюс + равнозначный минус» на on-kill/on-tick/`STATUS_REMOVED` (в т.ч. глобальные — `reach: 'global'`).

> **Важно:** текущий набор правил, предметов и способностей — тестовый: он создан для проверки работоспособности механик, а не как сбалансированный стартовый контент. Ориентируйтесь на него как на примеры использования DSL, а не как на готовый дизайн.

- Файлы: `src/simulation/content-rules/` (`types.ts`, `rules.ts`, `world-rules/global-rules.ts`).

## 5. Предметы и экипировка

- **Слоты экипировки (3):** weapon / armor / amulet. У каждого шаблона экипировки есть `subtype` (подтип: мечи `sword`, кинжалы `dagger`, посохи `staff` и т.д.) и `level` (уровень ≥ 1; привязка дропа к этажам — отдельная задача). Фирменные свойства предмета задаются `fixedModifiers` — ID модификаторов из категории `modifiers` (stat — add/multiply к любому стату включая базовые характеристики, rule — контентное правило; заменили удалённые 2026-08-09 `equipModifiers`/`ruleIds` предметов). Также выдаются способности: `grantedAbilities` — гарантированные, `abilityPool` — одна роллится по весам при создании экземпляра (основа «проков» предметов).
- **Аффиксы (свойства экземпляра):** экземпляр экипировки несёт единый список `InventoryItem.affixes` (`origin: 'fixed' | 'rolled'`): сначала фирменные аффиксы (из `fixedModifiers` шаблона, детерминированы), затем до 2 случайных, ролленных при создании экземпляра из контентной категории `modifiers` (пул: `poolEligible: true` ∩ `applicableSubtypes` ∋ `subtype` предмета, исключая фирменные модификаторы и конфликтующие с ними ruleId): 1 положительный (взвешенно по `weight`) + до 1 отрицательного (с шансом `NEGATIVE_AFFIX_CHANCE = 0.5`). Модификатор — либо stat (модификатор характеристики; значение роллится из рейнжа уровня шаблона `ranges[level-1]` или детерминировано при `scaling: fixed`), либо rule (контентное правило, значение доступно правилу через `ParametrizedValue {type: 'ownerParam'}`). Значения фиксируются в экземпляре и показываются в карточке предмета единой секцией «Свойства» (случайные помечены ✦). Дизайн: `docs/game-design/equipment-modifiers-concept.md`. Именование: модификаторы и реликвии веток билдов — `mod_{ветка}_{имя}` / `relic_{ветка}_{имя}` (кровавая ветка — `blood`, 2026-08-30), универсальные — без слова ветки.
- **Расходники (`USE_ITEM`):** реализованы эффекты `heal` (value HP), `buff` (пока жёстко `regenerating`), `spawn_tile_effect` (бросок материала в точку с LOS: вода/масло/дым; `radius`, `range` в шаблоне), `damage` (бросок-взрыв: `frag_bomb`, `incendiary_bomb`), `applyStatus` (2026-08-30: наложение списка статусов `{statusType, duration}` на себя — `ritual_cut`). Итоговая дальность броска = `range` шаблона + стат `throwRange` персонажа (`getConsumableThrowRange`, учитывается в валидации и таргетинге). `teleport`/`identify` — заглушки в схеме.
- **Лут:** при смерти врага `lootDropTable` (взвешенное количество дропов) + `lootTable` (взвешенный выбор предметов) → дроп на свободную клетку рядом с трупом. Runtime random (не детерминировано seed'ом).
- **Инвентарь:** 20 ячеек, стаки (`stackable`/`maxStack`). У предметов есть `rarity` (common/rare/unique) и `value` — экономика не подключена (см. §10).
- Файлы: `src/simulation/systems/actions/equip-action.ts`, `use-item-action.ts`, `src/simulation/systems/item-affix-roll.ts`, `src/simulation/systems/world-reactions/post-death-loot-reaction.ts`, `src/content/templates/items/`, `src/content/templates/modifiers/`.

## 6. Мир и окружение

### 6.1 Слоистая модель клетки

Клетка = террейн (ровно 1) + максимум 1 эффект слоя `cover` + максимум 1 эффект слоя `aboveGround` + объекты по слотам + актор. Слоты объектов: `solid` (дверь, проп, poi — несовместим ни с чем), `floorFixture` (лестница, ловушка), `loot` (контейнер предмета). Замена эффекта в слое даёт механику «вода смывает масло» (и наоборот).

- Слоты — `src/simulation/state.ts` (`getPlacementSlot`, `canPlaceObjectAt`).

### 6.2 Террейны

Статичный базис клетки. Ручки шаблона: `walkable`, `moveCost` (AP за вход; песок = 2), `blocksLOS`, `standing` (псевдо-3D отрисовка), `tags` (`ground` — можно ставить эффекты и объекты), `ruleIds`. Существующие: `floor`, `sand`, `wall`.

- Файлы: `src/content/templates/terrains/`.
- Ограничение: `moveCost` влияет только на списание AP; автопуть и AI-pathfinding равностоимостные.

### 6.3 Тайловые эффекты (материалы)

Динамические материалы на клетках. Принцип «материал ≠ механика»: сами эффекты урона не наносят, всё поведение — через `ruleIds` и статусы. Движение не блокируют никогда; могут блокировать обзор (`blocksLOS`). Длительность тикает раз в раунд; `durationDecreasesWhenHasStatus` — тик только при наличии статуса (масло стоит вечно, пока не горит). Повторный спавн того же типа продлевает длительность.

- Существующие: `water` (cover, → `wet`), `oil` (cover, горит и взрывается), `smoke` (aboveGround, `blocksLOS`), `blood_puddle` (cover, → `bleeding` на 2 хода при входе и при появлении под существом, 2026-08-30).
- Статусы эффектов: шаблон `burning` (урон при входе, поджог стоящих, распространение на соседнее масло, взрыв при поджоге через world-реакцию, авто-поджог свежего масла рядом с огнём).
- Источники — расходники `water_ball`, `oil_bottle`, `smoke_bomb`, `blood_flask`.
- Файлы: `docs/architecture/TILE_EFFECTS.md`, `src/content/templates/tile-effects/`, `tile-effect-statuses/`.

### 6.4 Объекты

- **Двери:** открытие/закрытие (1 AP, с соседней клетки), HP/броня (разрушаемы), закрытая блокирует движение и LOS, горючие (`flammable` + `canHaveStatus: [burning]`), события дверей будят AI. У двери есть универсальное состояние «заперта» (`DoorEntity.isLocked`, интенты `LOCK_DOOR`/`UNLOCK_DOOR`): запертую нельзя открыть, она непроходима для AI, автопути и рывка. Шаблон может быть неразрушаемым (`indestructible` — движок обнуляет любой урон по такой двери). Примеры: `wooden_door` (3 HP), `boss_door` (неразрушаемая, негорючая — дверь босс-комнаты, см. §8).
- **Пропы:** разрушаемые, `blocksMovement`/`blocksLOS`, теги. Пример: `oil_barel` (`contains.oil`, `flammable`) — при гибели разливает масло, если горел — горящее.
- **POI (точки интереса):** неразрушаемые, непроходимые, разовость через `charges`, эффект декларативно через `ruleIds` на событие `POI_USED`. Оконные poi (`window` в шаблоне + механика в `src/simulation/systems/poi-windows/`): активация открывает модальное окно выбора, заряд тратится по `chargeSpentOn` (при активации или при выборе), выбор — действие `RESOLVE_POI_CHOICE` (1 AP; сама активация окна при `chargeSpentOn: 'resolution'` бесплатна — 0 AP), предложение хранится в `poi.offer` (переживает снапшот этажа). Примеры: `altar` (1 заряд, лечение 25), `relic_altar` (алтарь выбора реликвии: окно `relic_choice`, выбор 1 из `offerSize` реликвий пула `MapParams.relicPool`, нестакаемые имеющиеся исключаются; спавнится гарантированно в стартовой комнате через `fill.guaranteedPois` её типа комнаты — `startRoomTypeId` карты).
- **Ловушки:** проходимые, `initiallyHidden` (не видны до срабатывания), `oneShot` (одноразовая уничтожается; постоянная раскрывается и срабатывает повторно). Срабатывание — правило с триггером `ENTITY_MOVED`. Пример: `spikes` (одноразовые, 10 piercing). Обезвреживание не реализовано.
- Файлы: `src/content/templates/{doors,props,pois,traps}/`, рецепты `docs/recipes/add-poi.md`, `add-trap.md`.

### 6.5 Перемещения и столкновения

Интенты `JUMP`, `PUSH`, `TELEPORT_ENTITY`. Толчок: свободная клетка → перемещение; препятствие → `ENTITY_COLLIDED` (wall/actor/blocking-object). Глобальные правила: при столкновении после толчка обе стороны получают 5 blunt-урона и `dazed` на 2 хода — окружение становится оружием.

- Файлы: `src/simulation/systems/intents/push-intent-executer.ts`, `src/simulation/content-rules/world-rules/global-rules.ts`.

### 6.6 Зрение и туман войны

FOV игрока — recursive shadowcasting, радиус 8. Две сетки: `visible` (пересчёт после каждого действия) и `explored` (раз виденное — навсегда), сохраняются per-этаж. LOS блокируют независимо: террейн, закрытая дверь, проп, тайловый эффект с `blocksLOS` (дым). Таргетинг скиллов, расходников и дальней базовой атаки использует тот же FOV. У AI свой обзор (`aiSightRadius`).

- Ручки: `PLAYER_SIGHT_RANGE` (константа), `blocksLOS` на террейнах/пропах/эффектах, `aiSightRadius` у врагов.
- Файлы: `src/simulation/systems/fov.ts`.

### 6.7 Этажи и переходы

Подземелье — этажи 1..10 (`MAX_FLOOR`). Переход только игроком и только стоя на лестнице. Уходя с этажа, игра сохраняет снапшот (карта, сущности, explored, тайловые эффекты, RNG); при возврате этаж восстанавливается «как было» (эффекты не тикают, пока этаж неактивен). Игрок появляется на противоположной лестнице, AP восстанавливаются.

- Файлы: `src/simulation/systems/floor-transition-planner.ts`, шаблоны `src/content/templates/stairs/`.

## 7. AI врагов

«Стратегия решает что, утилиты — как». Стратегия выбирается `aiStrategyId` в шаблоне врага; состояние FSM — в `enemy.aiState`.

- **`hunter`** — FSM idle→chase→return: видит игрока → сближение и атака; теряет цель → идёт к последней позиции → возвращается домой.
- **`simple-boss`** — не двигается и не бьёт обычной атакой; видя игрока, **готовит** `aiPreparable`-способность (телеграф `ABILITY_PREPARED`) и исполняет её на следующий ход. Стан/немота отменяют подготовку.
- **`guardian-boss`** — первый босс: охотничий FSM + две стадии (порог 50% HP, поля `bossStage`/`bossTransitionPending` в `aiState`). Стадия 1: ближний бой, в конце хода готовит Налёт (`guardian_swoop`) — только если тактика `findCollisionLanding` находит точку приземления со столкновением игрока с препятствием (урон + dazed правилами столкновения), иначе придерживает. Переход: одноразовое немедленное комбо «подготовка `ground_slam` + каст `bulwark`». Стадия 2: приоритет комбо «Удар + Оборона» (по кулдаунам), Налёт заполняет окна. Оборона (1 ход) защищает подготовку в ход игрока и спадает тиком до хода босса. Зоны подготовленных скиллов подсвечиваются игроку (generic-телеграф через `getAffectedPositions` исполнителя).

Восприятие: `aiSightRadius` (default 6) + LOS; вне хода — уведомления о движении игрока и открытии/закрытии дверей.

- Ручки: `aiStrategyId`, `aiSightRadius`, innate `abilities`, флаг `aiPreparable` у способностей, `maxAp` врага, прямые боевые поля врага (`attack`/`armor`/`modifiers`).
- Файлы: `src/simulation/ai/`, `docs/agents/AI_SYSTEM.md` (`[DRAFT]` — источник правды код).

## 8. Генерация этажей

Единственная стратегия — `tree` (дерево комнат от спавна к выходу + коридоры с закрытыми дверями на концах). Seeded RNG — геометрия воспроизводима по seed.

Ручки `MapParams`: `width/height`, `minRooms/maxRooms`, `roomTypePool` (типы комнат этажа, weighted; у типа — `minDepth`/`maxPerFloor`, `minSize/maxSize` и `fill`: пулы врагов/предметов/пропов/ловушек/луж + `guaranteedPois`), `startRoomTypeId`, `relicPool`, `bossPool` (+ `bossRoomTypeId`/`rewardRoomTypeId`), `finalFloor` (номер финального этажа забега: спуск с него завершает забег победой вместо перехода дальше, roadMap 1.5; default = `MAX_FLOOR`). Плотности от площади комнаты (площадь/16 × density). Существующие карты: `default`, `floor_1`, `floor_2`.

**Босс-файт этажа (2026-08-14):** при заданном `bossPool` (шаблоны обязаны иметь `isBoss: true`) генератор назначает самому дальнему узлу дерева тип `boss` (родитель exit-узла), exit-узлу за ним — `reward` (оба типа с `weight: 0`, в ролл не входят; лестница вниз остаётся в комнате награды, там же алтарь лечения через `guaranteedPois`), спавнит одного случайного босса из пула в центре босс-комнаты и ставит на коридорах босс-комнаты неразрушаемые двери `boss_door` (тег `boss_room`). Контроллер босс-комнаты (`world-reactions/boss-room-reaction.ts`) при входе игрока при живом боссе внутри закрывает и запирает эти двери, при выходе игрока до победы — отпирает (босс преследует своим hunter-FSM), после смерти последнего босса — отпирает насовсем. У `floor_1` задан `bossPool: ['cat_guardian']`.

- Файлы: `src/simulation/systems/map-generation/`, `src/content/templates/maps/`.

## 9. Прогрессия и создание персонажа

- **Создание персонажа:** выбор шаблона игрока (`starterEquipment` на выбор, `baseStats`), распределение 10 очков по 4 характеристикам. Классов нет — «класс» = шаблон игрока + стартовый набор. 7 шаблонов в `src/content/templates/players/`.
- **Реликвии:** коллекция игрока (`PlayerEntity.relics`), выдача через `GRANT_RELIC` (выбор 1 из 3 на алтаре, см. §6.4). Коллекция отображается в UI панелью реликвий (`RelicsPanel`, правая колонка между экипировкой и инвентарём): одна строка ячеек с горизонтальным скроллом, стаки бейджем, детали и атмосферный текст — в поповере по наведению. Стартовый пул (roadmap 0.6) — 8 нестакаемых реликвий формата «плюс + минус», общий `relicPool` на всех этажах: огонь (`relic_salamander_heart` — урон оружия огненный, входящий огонь ×1.25), яд (`relic_venom_gland`, `relic_acid_blood`, `relic_plague_bearer`), дробящее оружие (`relic_thunderhead`), урон по ослабленным (`relic_opportunist`), урон оружия с ценой (`relic_blood_pact` — исходящий урон оружия +2, входящий урон оружия +1), лут (`relic_scavenger` — лечение за поднятие предмета, -5 maxHp). Минусы — отдельными правилами (второй ruleId) или отрицательными `statModifiers`.
- **Статистика забега (`runStats`):** убийства, поднятые предметы, убитые боссы (`defeatedBossIds`; имена для экрана концовки берутся локализованными из контента, признак босса — флаг `isBoss` шаблона). Фазы игры: `playing/dead/victory`.
- **Опыт и уровни — НЕ работают**, см. §10.

## 10. Пробелы: каких механик не хватает

Важно при планировании контента — эти вещи либо заготовки, либо отсутствуют.

### 10.1 Заявлено в схемах/типах, но не реализовано

| Механика | Что есть | Чего нет |
|---|---|---|
| Расходники damage/teleport/identify | значения в схеме эффектов | реализация (работают только heal/buff/spawn_tile_effect) |
| Экономика | `value`, тип `gold` у предметов | торговля, золото как механика |
| Сундуки | поле статистики `chestsOpened` | сами сундуки |
| `luck` | поле в `CharacterAttributes` | ни на что не влияет |
| Обезвреживание/поиск ловушек | концепт описан | обнаружение реализовано (способность `search`, kind `search`, 2026-08-23); обезвреживания (disarm) нет |

### 10.2 Ограничения генерации мира

- Генератор размещает врагов, лут, пропы (`oil_barel`), ловушки (`spikes`), лужи масла/воды, двери, лестницы и гарантированные poi — всё через типы комнат (`fill` у `roomType`; стартовой комнате назначается `MapParams.startRoomTypeId`); босс из `bossPool` спавнится отдельно в центре босс-комнаты (см. §8). Не спавнятся на этажах: песок и прочий не-floor террейн, `training_dummy` — только через debug-действия или доработку генератора.
- Стратегия генерации одна (`tree`); ручного размещения объектов в `MapParams` нет.
- Поэтажные `relicPool` (например, в floor-2) — мёртвый контент: `mapParams` фиксируются на floor_1 на весь забег.
- Мировой слой правил `terrain` (правила на террейнах) — отложенная фаза 6 слоистой модели; трансформация террейна правилами не реализована.

### 10.3 Ограничения AI и путей

- AI не учитывает тайловые эффекты, дым и `moveCost` при выборе пути/цели; не уклоняется от раскрытых ловушек (запланировано в фазе 6).
- Автопуть игрока равностоимостный — маршрут через песок не избегается.
- AI-стратегий две (`hunter`, `simple-boss`).

### 10.4 Ограничения выразительности правил

- Условия применяются и к модификаторам интентов: `modifyDamage` фильтруется по триггеру, тегам **и `conditions`** (`apply-intent-modifiers.ts`, покрыто тестом). ~~Ранее здесь ошибочно утверждалось, что условия не работают с `modifyDamage`.~~
- `ParametrizedValue` не поддерживает divide/add/max и ссылки на статы сущностей.
- Желаемые правила, которым не хватает выразительности DSL (выявлены при разборе ограничений): яд снижает урон. ~~AP при убийстве, лечение при убийстве~~ — реализованы 2026-08-30 (реликвии «Жатва»/«Кровавое эхо» кровавой ветки: `ENTITY_DIED` + `hasStatus` + слой `global`). (Блок щитом исключён 2026-08-04: выразим условным `modifyDamage multiply 0`.)
- Формализованный каталог игровых тегов не заведён (невыполненная фаза 3 типизации ID контента): теги — свободные строки без единого реестра и валидации.

### 10.5 Захардкожено в коде (не вынесено в контент)

- Эффект `buff` расходников — всегда `regenerating`.
- AI-стратегии — расширяются только кодом (+ запись в `src/content/ids.ts`).
