# Концепт кровавой ветки билдов (этаж 1)

> **Статус:** `[STABLE]` — реализован целиком (план [`docs/plans/bleed-builds-implementation.md`](../plans/bleed-builds-implementation.md), этапы 0–6, 2026-08-30). Числовые значения черновые; баланс — отдельным проходом с плейтестом (roadMap 1.4).
>
> **Назначение.** Ветка билдов первого этажа вокруг оружия «Зазубренный сырорез» (`weapon_sword_splinter_blade`, бывш. `common_splinter_blade`) и статуса `bleeding`. Документ фиксирует пять направлений плейстайла и **единый дедуплицированный пул контента**, из которого эти направления собираются комбинациями, — а не пять отдельных комплектов.
>
> Именование контента ветки — по конвенции `mod_blood_*` / `relic_blood_*` (см. §2, решения 2026-08-30).
>
> Связанные документы: [`floor-1-content-concept.md`](./floor-1-content-concept.md) (контент этажа 1, §4.3 мечи, §4.8 реликвии), [`mechanics-overview.md`](./mechanics-overview.md), [`CONTENT_RULES_EDGE_CASES.md`](../agents/CONTENT_RULES_EDGE_CASES.md). План реализации: [`docs/plans/bleed-builds-implementation.md`](../plans/bleed-builds-implementation.md).

## 1. Рамка

- **Ядро ветки:** `weapon_sword_splinter_blade` (меч, рубящий урон) с фирменным `mod_blood_on_hit` — каждый удар открывает кровотечение на 3 хода; пул скиллов `dash`/`cleave`.
- **Статус `bleeding`:** тик 2 HP внутреннего урона (`damage.internal.bleeding`), бронёй не режется; категория `wound`.
- **Пять осей плейстайла** (§5), обслуживаемые одним общим пулом из ~12 штук контента (§4). Дедупликация: одна штука на роль — один усилитель урона по кровоточащим (существующий `mod_blood_execute`), два sustain-триггера, один AP-движок.
- **Конвенция реликвий «плюс + равнозначный минус»** (по образцу `relic_acid_blood`, `relic_scavenger`, `relic_blood_pact`): у каждой новой реликвии есть отрицательный эффект сопоставимого веса (§4.2).
- Основной инструмент — существующий DSL контентных правил (триггеры на событиях, условия `hasStatus`/`eventRole`/`notSelfHit`, эффекты `heal`/`restoreAp`/`consumeAp`/`modifyDamage`/`dealDamage`/`spawnTileEffect`). Новых статусов не требуется.

### Ключевые ограничения движка, учтённые в дизайне

- **Атрибуция DoT-киллов:** тик кровотечения принадлежит жертве, поэтому правила «при убийстве» (`ENTITY_DIED` + `eventRole: source`) срабатывают только на добивание руками. В дизайне это использовано как фича (см. «Жатву», §4.2).
- **Порядок смерти (модель 1, зафиксирована 2026-08-30):** смерть — последнее, что происходит в волне: все реакции на смертельный урон (включая наложение on-hit статусов) разрешаются до `ENTITY_DIED`. Реакция на смерть видит всё, что успело наложиться смертельным ударом: враг, убитый первым ударом рубящего оружия, для on-death правил считается **кровоточащим**. Снапшотов «статусов до удара» в движке нет; если механике понадобится «статус существовал до удара» — это точечное исключение, вводимое отдельно.
- **`chance` не используется** — механики детерминированы (решение 2026-08-04).

## 2. Принятые решения (2026-08-30)

- Пять билдов реализуются **общим пулом контента**, а не пятью комплектами: игрок собирает гибриды через комбинации; слоты экипировки (1 броня, 1 амулет) сами ограничивают смешение.
- Дедупликация пула: один усилитель урона по кровоточащим (существующий `mod_blood_execute`), два sustain с разными триггерами («Пиявка» на тик, «Кровавое эхо» on-kill), один AP-движок («Жатва», on-kill; вариант «AP при наложении bleed» отложен — см. §7).
- У каждой новой реликвии — равнозначный минус (§4.2).
- Минус «Разрывателя» — детонация задевает владельца (селектор без `excludeSelf`), бесплатно механически и даёт позиционную игру.
- **Именование (2026-08-30):** контент ветки именуется `mod_blood_*` / `relic_blood_*`; универсальный контент — без слова ветки. Выполнены переименования: `mod_bleeding_on_hit` → `mod_blood_on_hit`, `mod_bleeding_execute` → `mod_blood_execute`. id правил движка (`weapon_bleeding_on_hit` и т.д.) не меняются.
- **Минус «Кровавого эха» (2026-08-30):** в модели 1 формулировка «убийство без кровотечения» недостижима без снапшотов — минус заменён на «когда у кого-нибудь спадает кровотечение, владелец получает 1 внутренний урон» (§4.2).

## 3. Движковые доработки (код)

1. ~~**Проверка края `ENTITY_DIED` + `hasStatus`**~~ — **проверено 2026-08-30: доработка не нужна.** Статусы с трупа не снимаются до конца раунда, `hasStatus` на трупе работает (прецедент — детонация бочек). Модель 1 порядка смерти фиксируется unit-тестами и документацией (`CONTENT_RULES_EDGE_CASES.md`).
2. **`applyStatus` в эффектах расходников** (`ConsumableEffectSchema` + resolve в `use-item-action.ts`, таргетинг self) — только для `ritual_cut` (§4.3). По образцу эффекта `damage` (floor-1-концепт, п.2 §3). Эффект принимает **список** статусов `{statusType, duration}` (решение 2026-08-30: надрез вешает два статуса).
3. **Глобальный слой сбора правил** (2026-08-30): слой `radius` собирает правила акторов только в радиусе 1 от события — для on-death реликвий (минусы «Жатвы» и «Кровавого эха») недостаточно. Опт-in поле правила (`reach: 'global'`), сбор помеченных правил всех живых акторов независимо от дистанции, с дедупликацией против слоёв `source`/`target`/`radius`.

## 4. Контент

### 4.1 Модификаторы (`src/content/templates/modifiers/`)

| ID | Имя | Подтипы | Что делает | Билды |
|---|---|---|---|---|
| `mod_blood_on_hit` (есть) | «Режущая» | sword | Каждый удар рубящим уроном открывает цели кровотечение на 3 хода. Фирменный модификатор сырореза | все |
| `mod_blood_execute` (есть) | «Добивающая» | sword | Удары оружием наносят +3 урона по кровоточащим целям — единый усилитель урона ветки | 1, ролл для всех |
| NEW `mod_blood_widening_wound` | «Рваные края» | sword | Удар по уже кровоточащей цели рассекает рану: кровотечение обновляется **до 5 ходов** (дольше базовых 3; `applyStatus` и так обновляет длительность, поэтому ценность — в увеличенной длительности). Rule-аффикс, `scaling: none` | 1, 3, 5 |
| NEW `mod_blood_thorns` | «Кровавые шипы» | light, heavy | Когда владельца бьют в ближнем бою, нападающий получает кровотечение на 2 хода (по образцу `armor_spiked_thorns`) | 2, 5 |
| NEW `mod_blood_frenzy` | «Берсерк» | talisman | Пока владелец сам кровоточит, его удары оружием наносят дополнительный урон (величина от уровня предмета, `scaling: perLevel`) | 4 |

### 4.2 Реликвии (`src/content/templates/relics/`) — плюс + равнозначный минус

Минус помечается `polarity: 'negative'` (поддержано в UI). Числа черновые.

**`relic_blood_leech` «Пиявка»** (билд 2)
- Плюс: каждый тик кровотечения у врагов рядом лечит владельца на 1 HP.
- Минус «Истощение»: −5 к максимальному здоровью (`statModifiers`) — пиявка уже присосалась.
- Логика пары: регенерация в бою компенсирует урезанный запас HP, а не идёт сверху.

**`relic_blood_echo` «Кровавое эхо»** (билды 1, 2)
- Плюс: владелец своим ударом добивает кровоточащего врага → лечится на 2 HP.
- Минус «Эхо жаждет крови» (формулировка 2026-08-30): когда у кого-нибудь **спадает** кровотечение (`STATUS_REMOVED` по `bleeding` у любой сущности), владелец получает 1 внутренний урон. Смерть статусов не снимает — добивание кровоточащего не штрафуется; штрафуются спадание у выживших, вытеснение и стеки → 0.
- Логика пары: билд обязан добивать раненых до спадания ран — «недоеденная» кровь возвращается болью. Анти-синергия с «Пиявкой» (она хочет долгих чужих тиков) — осознанное трение.

**`relic_blood_reaper` «Жатва»** (билды 1, 3)
- Плюс: владелец своим ударом добивает кровоточащего врага → возвращается 1 AP (`restoreAp {amount: 1}`, ручка п.12 §3 floor-1-концепта).
- Минус «Чужой урожай»: кровоточащий враг умирает не от руки владельца (тики, мышеловка, взрыв) → владелец **теряет** 1 AP. Требует глобальный слой сбора правил (п.3 §3).
- Логика пары: зеркальная пара на одном триггере смерти; пассивное истекание врагов наказывается, билд обязан добивать руками. Единственный AP-движок пула.

**`relic_blood_fuel` «Кровавое топливо»** (билд 4)
- Плюс: каждый тик собственного кровотечения владельца возвращает 1 AP.
- Минус «Обескровлен»: когда кровотечение владельца спадает, он теряет 1 AP (`STATUS_REMOVED` по типу `bleeding` на владельце).
- Логика пары: 2 HP/тик — встроенная цена плюса, минус бьёт в момент выхода из «берсерк-режима»: нельзя бесплатно подзарядиться и сразу уйти.

**`relic_blood_rupture` «Разрыватель»** (билд 5)
- Плюс: кровоточащий враг при смерти разрывается: все в радиусе 1 получают 4 внутреннего урона, выжившие подхватывают кровотечение на 2 хода (два правила на одном триггере).
- Минус: детонация **не разбирает своих** — владелец рядом получает те же 4 внутреннего урона (селектор без `excludeSelf`).
- Логика пары: позиционная игра — детонацию провоцировать на дистанции, а не в упор. По модели 1 ваншот рубящим оружием тоже детонирует (труп успевает покрыться кровью) — принято как свойство модели.

Намеренные анти-синергии: «Пиявка» лечит только от чужих тиков (с «Кровавым топливом» бесконечности нет), «Разрыватель» наказывает гибрид с билдами ближнего боя.

### 4.3 Тайловый эффект и расходники

- NEW `blood_puddle` «Кровавая лужа» (слой `cover`): всякий, кто заходит на лужу или оказывается в ней при появлении, получает кровотечение на 2 хода. Чистый контент — копия механики `water`/`wet` (правила на `ENTITY_MOVED` и `TILE_EFFECT_CHANGED` + `isNew`).
- NEW `blood_flask` «Флакон крови» — метаемый расходник: разбивается лужей крови (радиус 1, дальность броска 2, как `flour_pouch`). Билды 2, 5.
- NEW `ritual_cut` «Ритуальный надрез» — расходник: владелец наносит себе ритуальную рану (кровотечение на себя, 3 хода) и входит в боевой транс (`empowered`, +2 урона, 2 хода). Требует движковый п.2 §3 этого документа. Билд 4.

### 4.4 Статусы

Новых не требуется: `bleeding`/`swift`/`empowered` покрывают ветку.

## 5. Билды (оси плейстайла)

1. **«Жнец» — казнь кровоточащих.** Петля: `cleave`/`dash` раздают bleed по пачке → добивание усиленными ударами; убийства возвращают темп (AP) и здоровье. Набор: сырорез + `mod_blood_execute` + `mod_blood_widening_wound` + «Кровавое эхо» + «Жатва».
2. **«Пиявка» — вампиризм и аутласт.** Петля: встать в гущу под «Стойкой», раздать bleed и лечиться чужими тиками. Набор: сырорез + тяжёлая броня с `mod_blood_thorns` + «Пиявка» + «Флакон крови»; мышеловка (bleed+rooted) держит цель рядом.
3. **«Боевая пляска» — мобильный DoT.** Петля: вбежал → повесил bleed → вышел; темп за счёт AP-движка. Набор: сырорез + `mod_blood_widening_wound` + лёгкая броня (`swift`/`dash`) + «Жатва»; `smoke_bomb`/`flour_pouch` для разрыва дистанции.
4. **«Ритуалист» — игра от собственной крови.** Петля: сознательно вешать bleed на себя и конвертировать тики в AP и урон. Набор: «Ритуальный надрез» + «Кровавое топливо» + `mod_blood_frenzy` (+ «Пиявка» как страховка). Синергия с существующей `relic_blood_pact`. Высокий потолок, высокая цена ошибки.
5. **«Мясник» — цепное кровотечение.** Петля: bleed как зараза — расплескивается и детонирует при смерти носителя. Набор: сырорез (`cleave` — ядро) + `mod_blood_widening_wound` + «Разрыватель» + «Флакон крови». Честная слабость: против одиночного босса (`cat_guardian`) цепочки не работают — босс-часть берётся через `mod_blood_execute`.

- **`weapon_sword_splinter_blade`** (бывш. `common_splinter_blade`) — ядро ветки (фирменный `mod_blood_on_hit`); пул ролла мечей: `mod_blood_execute` + `mod_blood_widening_wound`. ~~Рассинхрон урона `{1,2}` vs `{4,6}`~~ — исправлен 2026-08-30 при возврате из legacy: в коде `{4,6}`.

- **`weapon_sword_flaming`** (бывш. `common_flaming_sword`, чистый fire) — ветку не поддерживает, остаётся мостом к линии Алхимика.
- **Броня** `armor_heavy_tin_plate`, `armor_light_patch_cloak`/`armor_light_spiked_cloak` — роллят `mod_blood_thorns`; фирменный `mod_spiked_thorns` шипованного плаща не меняется (возвращён из legacy 2026-08-30).

- **Реликвии** — в `starterRelicPool` будущего шаблона «Боец» (floor-1-концепт §4.10) и общий `relicPool`.
- **Расходники** — в пулы наполнения типов комнат (`normal`), рядом с `flour_pouch`.

## 7. Отложенные вопросы

- **Мёртвый аффикс на piercing-мечах:** принять как риск ролла или фильтровать пул аффиксов по `damageDistribution` оружия (доработка ролла).
- **Вариант «AP при наложении bleed»** (вместо/вместе с «Жатвой»): требует лимитера срабатываний правила за ход (иначе `cleave` по пачке генерирует AP из воздуха). Отложен до появления лимитера.
- **Пул амулетов этажа:** floor-1-концепт предполагал один MVP-амулет («Тусклая бусина»), тестовых сейчас 4 — какие войдут в пул этажа и куда ляжет `mod_blood_frenzy`, решать при контентном проходе.
