# Mousefall — Roadmap крупными мазками

> Черновик плана на ревью.  
> Цель: из текущего прототипа с 10 одинаковыми уровнями сделать полноценный 10-этажный roguelike.

---

## Видение

- **10 этажей**, каждый — уникальный биом с собственными пулами врагов, предметов и боссов.
- **Босс на каждом этаже**: случайный из пула этого этажа/биома. Переход на следующий этаж — только после его убийства.
- **Прокачка внутри забега**: через предметы — заменяемая экипировка + накапливаемые реликвии. Реликвия выбирается (1 из 3) на алтаре выбора в начале каждого этажа. Классического XP/level-up нет. См. [`docs/game-design/progression-concept.md`](./docs/game-design/progression-concept.md). Реализовано в этапе 0 (2026-08-06, план `docs/plans/stage-0-relics-altar.md`).
- **Экономика**: золото с врагов/сундуков/боссов, магазин между этажами, возможный крафт/улучшение снаряжения.
- **Мета-прогрессия**: нет. Сейчас — «трушный рогалик».
- **UI/анимации и сохранения**: в последнюю очередь, после стабилизации игрового цикла.

## Этап 1. Первый этаж + первый босс

> Цель: есть работающий вертикальный срез — один полноценный этаж с боссом, который можно пройти.

### 1.1 Скиллы стартового снаряжения (Перед этим доработать эги в оружии. Переделать тип урона под тэги)
> Цель: у каждого вида начального снаряжения есть осмысленный выбор из 2 активных скиллов.

- Создать 2 скилла для оружия (например, сильный удар и серия ударов).
- Создать 2 скилла для брони (например, блок и контратака).
- Создать 2 скилла для амулета (например, лечение и бафф).
- Оформить все скиллы как `AbilityTemplate` и привязать к стартовым предметам через `grantedAbilities`.
- Проверить, что скиллы корректно выдаются при старте забега и отображаются в панели скиллов.

### 1.2 Генерация и параметры первого этажа
- Генерация этажа переводится на **типы комнат**: тип комнаты = контентный шаблон (вес, ограничения размещения, пулы и плотности наполнения, гарантированные объекты); генератор назначает типы узлам дерева комнат и наполняет каждую по её шаблону.
- Стартовый набор типов этажа 1: `start` (алтарь выбора реликвии), `normal` (обычные враги, лут, колючки по пулам), `elite` (сильные враги, бочки с маслом, повышенная награда), `boss` (босс + запирающиеся двери, см. 1.3), `reward` (лестница + алтарь лечения + пул лута босса).
- Генератор сохраняет границы и типы комнат в состояние этажа (универсально — пригодится для магазинов и особых комнат).
- Задать `MapParams` для 1-го этажа: размер, плотность врагов, плотность предметов.
- Определить визуальный стиль/биом первого этажа.
- Спавн врагов и предметов по пулю для 1-го этажа.

### 1.3 Первый босс — Кот-Страж
- **Концепция:** тяжеловооружённый босс-первого этажа. Механики утверждены: см. [`docs/game-design/first-boss-concept.md`](./docs/game-design/first-boss-concept.md) (способности Глухая оборона / Налёт / Удар по земле, две стадии с переходом на 50% HP). Концепт заменяет исходную заготовку «щит/парирование» ниже: вариант щита выбран (периодическая неуязвимость — Глухая оборона), парирование исключено.
- **Механики (историческая заготовка, заменена концептом):**
  - **Щит:** пассивное снижение входящего урона или периодическое активирование неуязвимости (вариант — при дизайне босса, см. «Отложенные доработки»).
  - **Парирование:** при получении удара в определённом состоянии наносит ответный урон.
  - **Тяжёлая броня:** высокое здоровье и броня, низкая скорость.
- **Принцип:** босс реализуется контентом на существующей системе правил, **без босс-специфичного кода** — нужен скилл → добавляем скилл, предмет → предмет, правило → правило (правила привязываются к врагу через экипировку и статусы). ~~Единственная доработка — обобщённый исполнитель self-buff способности (`statusType`/`duration` из шаблона способности) вместо захардкоженного `counterattackSkill`~~ — выполнено 2026-08-10 (поле `selfBuff` шаблона + fallback в `getSkillExecutor`, план `docs/plans/first-boss-implementation.md`, шаг 3; актуализировано 2026-08-11: вид `kind: 'selfBuff'` в union шаблона + фабрика `KIND_FACTORIES`, план `docs/plans/ability-templates-kind-union.md`). ~~Семантика `multiply 0` против «минимум 1 урона»~~ — вопрос снят 2026-08-10: пол min-1 удалён из расчёта урона (сохранён только для процентного урона через `min: 1` в правилах), `multiply 0` даёт 0.
- **Босс как контент:** флаг `isBoss` в шаблоне сущности заменяет захардкоженный `BOSS_TEMPLATE_IDS`; экран концовки переводится на имена боссов из контента. Пул боссов — `bossPool` в `MapParams` (по образцу `enemyPool`/`itemPool`), генератор гарантированно размещает случайного босса из пула.
- **Босс-комната (гейт перехода):** генератор помечает дальнюю от спавна комнату босс-комнатой и строит за ней комнату награды, достижимую только через босс-комнату; в комнате награды — лестница вниз и алтарь лечения (до реализации сундуков награда — отдельный пул лута босса).
- **Двери босс-комнаты:** особый шаблон — неразрушаемые, негорючие, с новым универсальным состоянием двери «заперта». Логика: игрок вошёл в босс-комнату → двери закрываются и запираются (триггер — сам факт входа, безусловно); все боссы комнаты мертвы → отпираются насовсем; игрок любым способом вышел до победы → отпираются, при этом урон боссу **сохраняется** (без сброса HP), а босс выходит из комнаты и **преследует** игрока. Отложенная доработка: закрытие по «рычагу» (см. «Отложенные доработки», этап 3).

### 1.4 Базовый контент 1-го этажа
- Пул врагов для 1-го этажа (можно на основе текущих + 1 новый).
- Пул предметов для 1-го этажа.
- Базовые расходники. Три реализованных типа эффектов (`heal`, `buff`, `spawn_tile_effect`) остаются как есть; при дизайне определяются состав расходников, судьба заглушек (`damage`, `teleport`, `identify`) и обобщение `buff` на `statusType` из шаблона. Ориентиры: `teleport` — осмысленный способ побега из запертой босс-комнаты (связка с преследованием босса, 1.3); боевая `damage`-бомба и свитки — этап 2.3.
- Лечение — **редкий, дефицитный ресурс**: алтарь восстановления HP (комната награды) + редкие расходники лечения. Конкретные числа (бюджет лечения на этаж, стартовый инвентарь) — при балансном проходе этого пункта и плейтесте.
- Баланс значений/длительностей яда и деза, иммунитеты врагов — этим же проходом.
- Слияние стопок при подборе: слияние в существующую стопку до `maxStack` + валидация «`stackable` несовместим с `abilityPool`» (экземпляры с ролленными способностями не сливаются) + тесты. Разделение стопок и частичный перенос — этап 2.3.

### 1.5 Условие победы в забеге
- После убийства босса 1-го этажа — переход на следующий этаж (заглушка/тот же биом допустим на этом этапе).
- Финальная победа временно = прохождение 1-го этажа.

**Критерий готовности:** можно начать забег и пройти 1 этаж, убив босса.

### 4.2 Материалы и ресурсы
- Ресурсы с врагов/сундуков/боссов.
- Простая система крафта/сборки.

### 4.3 Durability и износ
- **CHEESE_ARMOR — сырная броня.** Броня из сыра даёт навык «Укус»: персонаж откусывает кусок брони, восстанавливая здоровье, но уменьшая прочность брони. При прочности 0 броня съедается и исчезает.
  - Добавить `CheeseArmor` с полем `durability`.
  - Реализовать навык `BiteSkill`, доступный только при надетой сырной броне.
  - Применить лечение к сущности и износ к броне; уничтожить предмет при прочности 0.
- Ремонт предметов.
- Универсальная механика durability для других предметов (при необходимости).

### 4.4 Баланс экономики
- Цены, доход с этажа, инфляция, стоимость улучшений.

**Критерий готовности:** крафт/улучшение интегрированы в цикл и используются игроком.

## Главные риски / технический долг

- Сохранения отсутствуют полностью.
- Все этажи генерируются по одним параметрам.
- Нет босс-шаблонов и механики босс-файта (флаг `isBoss`, босс-комната — см. этап 1.3).
- Стопки предметов не работают (слияние при подборе — этап 1.4).
- `value` предметов нигде не используется.
